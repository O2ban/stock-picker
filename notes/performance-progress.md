# 选股性能优化进展（2026-10-01）

## 目标
全市场选股达到通达信/同花顺级别（1-2 秒），核心手段是指标预计算入库 + 消除重复取数。

## 已完成

### 阶段 1：指标预计算入库（已落库）
- 表：`daily_indicators`、`weekly_kline`、`weekly_indicators`、`precompute_meta`（全部建在 kline-trainer 的 kline.db 内，**不另建库**）
- 全量结果：日线指标 9,429,949 条、周线指标 1,989,715 条、周线 1,989,715 条
- 指标档位（用户已拍板只用四档）：MA5/10/20/60、VR5/10/20/60
- 复权只跑 qfq；停牌日 close 用前一日填充对齐通达信；量比口径 = 当天量 ÷ 前 N 日均量（不含当天）
- 耗时约 2 分 17 秒

### 阶段 2：消除重复取数（已生效）
- 原 `runScreen` 每只票调用 `loadRows` 2~5 次（每条件 1 次 + 算分 1 次 + 汇总 1 次）
- 改为每票只取 1 次 `{daily, weekly}`，全部条件与评分复用同一份数据
- 效果：扫描计算环节从数十秒降到 **424 ms**

### 阶段 3：预计算查表 + 当天实时补齐（已生效，历史天一律不重算）
- `buildLoader` 批量 `loadIndicators` / `loadWeeklyIndicators`，按 code 分组进内存
- `mapDailyRow` 把库内行映射成引擎行结构（date/o/h/l/c/vol/amount + ma5..ma60）
- `indicatorResult` 改为**优先读行上的 ma5/10/20/60 与 vr5/10/20/60**，列缺失才回退现场 sma
- 当天尚未入库 → `applyRealtimeToDaily` 用实时价补最后一根 K 线并重算该日 MA/VR
- **口径已统一**：`validateStrategy` 改为失败抛异常（原先返回错误值，server 侧按 `if(err)` 判导致误报）

## 实测数据（2026-10-01，默认策略 starter）

| 指标 | 数值 |
|---|---|
| 全市场扫描 | 5574 只 |
| 命中 | 566 只（取前 100） |
| **总耗时** | **13,847 ms** |
| 批量取数耗时 | 13,423 ms（**占 97%**） |
| 扫描比对耗时 | 424 ms（占 3%） |

基线对比：改造前 33.7s → 现在 13.8s。

## 关键结论（推翻此前判断）

1. **重复取数已解决，但重复取数不是主要瓶颈。** 降到 1 次后扫描环节从数十秒掉到 0.4s，说明"每条件重算"确实是大头，但**总耗时的大头转移到了批量取数**。
2. **当前真正的瓶颈是"读了太多用不上的行"。** 每票取 150 天日线（约 36 万行）+ 周线指标，合计约 76 万行进内存，而单票判断实际只需最后几十行。
3. 下一步应让数据库**只返回判断所需的那几行**（按条件所需 length 反推最大回看长度），而不是整段搬进来。这会改动 `runScreen` 的取数方式，性质上属于此前列的"第二条路"（预计算专用入口），但 engine 的条件判断框架、评分、排序、输出格式均无需改动。
