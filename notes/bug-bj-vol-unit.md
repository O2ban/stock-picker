# 北交所分时成交量差100倍修复

## 现象
对比分时归档与日K时，北交所18只票的成交量普遍差100倍（分时累计404.99手 vs 日K 40499.3股），沪深完全一致。

## 根因
`src/quotes.js` `parseTimeline` 第173行：
- `volDivisor` 默认值写死 `100`（按「股」处理，需÷100得到「手」）
- 探测循环靠「成交额÷累计量」反推单位，但**北交所分时每行只有3字段**（`0930 16.26 413`，无成交额）
- 探测循环因 `f.length<4` 全部跳过，`volDivisor` 停在100，把本来就是「手」的量又除100

**板块基线**（实测确认）：
- 沪深/北交所：腾讯分时返回的量是「手」（`amount/vol÷price≈100`）
- 科创板 sh688/689：返回的是「股」（需÷100）

**日K库的量是对的**：`amount/vol÷close≈100`，说明库里的 vol 就是手口径。之前怀疑日K量也错是误判。

## 修复
在探测循环前按板块给兜底默认值：
```js
const isStar = code.startsWith('sh688') || code.startsWith('sh689');
const isBj = code.startsWith('bj');
let volDivisor = (isStar && !isBj) ? 100 : 1;   // 探测不到成交额时：科创板=股(÷100)，北交所/其余=手(÷1)
```
有成交额时仍走探测循环覆盖。

## 验证
- 修复后重拉：`bj920006` 累计40499手，与日K 40499.3手一致
- 对比脚本中不再出现北交所 vol 差异

## 归档数据修复
- `scripts/archive-intraday-min.js` 只拉「当天清单里的票」，旧清单里的北交所票无法重拉
- 手写 `/tmp/refix-bj-archive.mjs` 遍历所有归档里的 bj 文件逐只覆写
- 最终归档里只剩4只可修（11-18：bj920050/249/642，11-19：bj920832），其余11-12旧归档已超腾讯5日回溯窗口、数据丢失
