在 stock-picker 分时策略的口径核查中发现三类典型情况，可作为同类工作的方法模板：
1) 已落实——代码里每个条件都有对应判定点，可直接给出文件:行号证据。
2) 文案漂移——策略 JSON 的说明文字写“当天最高涨幅 1%~3%”，但实际参数是 minPct:1/maxPct:2；或代码注释写“每 5 分钟跑一次”而实际 everyMin:1。这类不影响执行结果但会误导用户按说明读口径，应主动改文案。
3) 需求未落实成参数——“突破买点前最高点且有足够幅度”在代码里只有 p > preHigh[j]（严格大于即算突破），全库搜不到任何幅度阈值参数。“足够幅度”若确实是用户要求，则当前实现只落实了“突破”未落实“幅度”，必须回问用户量化定义，不能自行认定为已满足。
另一个半落实案例：“孤零零一根大阳量不构成买点”只落实了一半——缩量段 pileMin=3、上拉段 upMin=2 都有下限，但最前面“先放量”段没有最小根数，理论上单根也算数。
结论用语应明确分层：已落实 / 有出入（文案）/ 需运行验证或待用户拍板（无参数对应）。同时注意“水上”有两层语义必须分开核：高于日线昨收（s.prev）与高于分时中线（(当日累计最高+最低)/2），是两处独立判定，不可混谈。
