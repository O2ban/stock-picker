stock-picker 取数改动收尾时的审查处置经验：

一、P2 误报的识别方法：审查报告标出「量比计算在某个回退分支里把当天也算进了分母」，但核对当前代码发现早就是「不含当天」的写法，两套对照备份里也能看到这行修改早就存在，与本次取数改动无关。判断一个审查问题是「本次引入」还是「历史遗留」，应查两套备份的差异，而非只看当前代码有没有这行。

二、P3 级既有问题（4 条，均为改动前就有，不属于本次改动带出）：页面误判休市后不会自动解除、服务端时间依赖服务器本地时区、某只股票当天除权时盘中涨幅短暂失真、图已画好后回源失败会被回滚。按「没让改的地方不动」的原则未碰。

三、审查同时确认了本次改动最担心的四点都没有问题：历史基准日不会混进今天的价格、没走完的周不会被提前算进去、停牌和节假日不会造出假 K 线、缓存浅拷贝不会互相串数据。
