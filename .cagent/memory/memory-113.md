stock-picker 分时接口 fetchTimeline 在加 3 秒轮询后暴露出一个缺陷：请求失败时不缓存，客户端每 3 秒重试一次直穿上游，上游真挂掉时会被打穿。修复方式是把失败结果也写入 _tlCache 并打 err 标记，8 秒内重复请求直接返回缓存的失败结果。实测无效代码第二次请求 1.1ms 返回 502（首次 17ms 打到上游）。凡是高频轮询的接口都应默认加失败负缓存，这是防止上游故障被放大成请求风暴的通用模式。
