本项目用户在收到问题诊断后，偏好这种回复结构：先说清根因（并明确否定误导性方向，如『网络是正常的』），再列改动不大的修复清单并标注优先级（第 1 条必须做、第 2 条顺手做、第 3 条可选），最后问『要我现在动手改吗』并给出自己的倾向。这种『结论先行 + 分档建议 + 显式征询』的沟通方式适合在本项目沿用。
