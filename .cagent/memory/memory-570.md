stock-picker 换股瞬间的异常帧（如 25.14 / -1306.74 / -98.11%）不是数据源问题：图表已切到新股，但上层 state 里『当前是哪只股票』的标记要等切换动画结束才更新，这几百毫秒里 3 秒行情轮询把上一只股票的报价带回并通过了校验，被写进已经属于新股的面板，于是新旧股票数据被拼成同一行。修复方式：在行情回填的最内层加一道身份校验——带回的股票代码与当前股票不一致就丢弃，其余逻辑不动。这类『两条数据通道抢跑』的错配在日K/分时共用行情条时都会出现，任何带异步轮询+本地状态切换的看盘界面都应做同源身份校验。
